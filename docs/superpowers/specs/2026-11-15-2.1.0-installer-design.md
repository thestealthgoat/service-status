# Service Status 2.1.0: new installer

Approved 2026-11-15.

## Why

The updater replaces only the app's code (`server.js`, `index.html`). These changes live in the app shell (`main.js`,
Electron, signing), so they need a new installer:

- Updates sit waiting for someone to press Restart, sometimes with a Restart button on the booth screen mid-service.
- Other churches now install the app, and every one of them takes each release the moment it's pushed.
- The app is ad-hoc signed, so macOS refuses it until someone finds **Open Anyway**.
- After a reboot, the booth Mac doesn't start Service Status again on its own.

## Goals

1. **Updates apply on their own.** A downloaded update installs itself between 3:00 and 5:00 AM local time, unless a
   Planning Center service time is within 2 hours. The restart doesn't bring the window forward (it shows inactive).
   The Restart button stays.
2. **Beta channel.** Settings → **Updates: Stable / Beta**, with Stable the default. The booth Mac runs Beta. Releases
   go to Beta first and reach Stable only when the user says "promote it".
3. **Launch at login.** On by default, with a switch in Settings.
4. **Signed and notarized.** The app is signed with Developer ID Application (hardened runtime) and the installer with
   Developer ID Installer. The installer is notarized and stapled, so macOS opens it with no warning.
5. **Electron:** the newest 45.x that's at least 14 days old on build day (45.2.1 today).
6. **Version 2.1.0 everywhere,** with the current code bundled, so a new install needs no first-run update.

## Non-goals and constraints

- No forced reinstall. Existing 2.0.0 installs keep getting code updates (`min_shell` stays `2.0.0`); code must keep
  working on the 2.0.0 shell. Settings controls that need the new shell are hidden on old shells.
- No new screens or timing features. Those keep shipping through the updater.
- Certificates and the notary password never pass through Claude. The user imports the certificates and saves the
  notary login as the keychain profile `service-status`; builds refer only to that profile name.
- The booth Mac is never restarted or scripted by Claude. The user installs 2.1.0 there.

## Approaches

1. **Package with `@electron/packager` + sign/notarize with Apple's tools on the booth Mac (chosen).** It reuses
   the current `distribution.xml` (separate Intel/Apple Silicon packages) and needs only Node, which is already
   installed, and the user's certificates.
2. electron-builder end to end. Rejected: a large toolchain that replaces the working installer layout.
3. A cloud CI build (GitHub Actions). Rejected for now: the Developer ID private keys would have to live in GitHub
   secrets. Revisit if releases become frequent.

## Decided details

- Feeds: `update/latest.json` (Stable) and `update/beta.json` (Beta; falls back to Stable when it's missing).
  `tools/publish_update.py --beta` writes only `beta.json`; `tools/promote.py` copies Beta's version to Stable.
- Quiet window: a pure helper `quietToApply(now, serviceStarts)` decides when an update may apply; unit-tested.
- Quiet restart: `app.relaunch({ args: [..., '--quiet'] })`. With `--quiet`, the window is created with
  `show: false`, then `showInactive()`.
- Login item: `app.setLoginItemSettings({ openAtLogin })` from config `launch_at_login`, default true.
- Info.plist gains `NSLocalNetworkUsageDescription` (phones, and ProPresenter on another computer).
- Entitlements: `com.apple.security.cs.allow-jit` and `com.apple.security.cs.allow-unsigned-executable-memory`
  (Electron under hardened runtime).
- Release: `Service Status Installer.pkg` on GitHub release `v2.1.0`, and the README install steps lose "Open Anyway".
