# Service Status 2.1.0 Installer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a signed, notarized 2.1.0 installer whose shell applies updates overnight, supports a Beta channel and launches at login.

**Architecture:** Shell changes go in `src/main.js`; settings plumbing in `src/server.js` + `src/index.html` (which
also ship through the updater and must keep working on the 2.0.0 shell); a new `tools/build_installer.sh` packages
both architectures with `@electron/packager`, signs, builds the installer, notarizes and staples it.

**Tech Stack:** Electron 45.x, Node test runner, Apple `codesign` / `pkgbuild` / `productbuild` / `notarytool` / `stapler`.

**Spec:** `docs/superpowers/specs/2026-11-15-2.1.0-installer-design.md`

## Global Constraints

- `min_shell` stays `2.0.0`. Code must run on the 2.0.0 shell; shell-only controls show only when `update.shell >= 2.1.0`.
- Quiet window: 03:00–05:00 local, and no service start within 2 h.
- Keychain profile name `service-status`. Never read, print or pass a password or key.
- Electron: newest 45.x ≥ 14 days old on build day.
- Claude never installs on, restarts or scripts the booth Mac's app.

## Review Focus

- An update downloaded at 4:59 AM with the next check at 5:05 → it waits until the next night (no apply outside the window).
- A Wednesday 6 PM service → a 3 AM apply is unaffected; a hypothetical 4 AM event → skipped.
- Beta selected but `beta.json` missing (before the first beta publish) → falls back to `latest.json`, no error.
- The 2.0.0 shell receiving 2.1.x code → no Beta/Login controls, nothing breaks.
- A notarization rejection → the build stops with Apple's log, and no pkg is released.

### Task 1: Quiet-window and channel helpers (pure, tested)

**Files:** Create `src/shell.js` (required by `main.js`; plain functions, no Electron); Create `tests/shell.test.js`

**Interfaces:**
- `quietToApply(now: Date, serviceStarts: Date[]) -> boolean`
- `feedUrl(channel: 'stable'|'beta') -> string`, `feedFallback(channel) -> string|null`

- [ ] Tests: 3:30 AM with no services → true; 2:59 → false; 5:00 → false; 3:30 with a service at 5:00 → false; with a service at 6:00 → true (exactly 2 h 30 m). Beta URL ends in `update/beta.json` and falls back to `latest.json`; Stable has no fallback.
- [ ] Implement → `node --test tests/` passes.

### Task 2: Shell (`main.js`)

**Files:** Modify `src/main.js`, `src/package.json` (version 2.1.0)

**Interfaces:**
- Consumes: Task 1 helpers; `service.cfg.update_channel`, `service.cfg.launch_at_login`; `service.nextServiceStarts() -> Date[]` (Task 3)

- [ ] `checkForUpdate` fetches `feedUrl(channel)`, then `feedFallback` on a 404.
- [ ] Every 10 min: `update.status === 'ready' && quietToApply(new Date(), service.nextServiceStarts())` → `quietRestart()`.
- [ ] `quietRestart()` = `app.relaunch({ args: [...process.argv.slice(1).filter(a => a !== '--quiet'), '--quiet'] }); app.exit(0)`; on start with `--quiet`: window `show: false` then `showInactive()`.
- [ ] `app.setLoginItemSettings({ openAtLogin: cfg.launch_at_login !== false })` at start and when the setting changes.
- [ ] Verify by running the shell from source with `npx electron@<ver> src` on a test config dir: the quiet restart comes up inactive, and the login item shows in System Settings → General → Login Items.

### Task 3: Settings plumbing (ships through the updater too)

**Files:** Modify `src/server.js` (allowed keys `update_channel`, `launch_at_login`; `nextServiceStarts()`; `publicSettings` includes them and `shell`), `src/index.html` (Updates select + Launch at login switch, shown only when `shell >= 2.1.0`)

- [ ] Test: `nextServiceStarts()` returns today's and tomorrow's PCO service times from the current pick (unit test with a stub plan).
- [ ] UI check: ui_check PASS on all four screens; Settings on a 2.0.0 shell shows neither control.

### Task 4: Feeds and publish tools

**Files:** Modify `tools/publish_update.py` (`--beta`); Create `tools/promote.py`

- [ ] `publish_update.py 2.1.1 "notes" --beta` writes only `update/beta.json`; `promote.py` copies `beta.json` to `latest.json` (refuses if Beta isn't newer than Stable).

### Task 5: Installer build

**Files:** Create `tools/build_installer.sh`, `installer/entitlements.plist`; Modify `installer/pkg/distribution.xml` (version 2.1.0)

- [ ] Unsigned dry run (works before the certificates arrive): package x64 + arm64, run `pkgbuild` / `productbuild`, check `pkgutil --expand` and that each `.app` launches its bundled code (`ELECTRON_RUN_AS_NODE=1 … -e "require('./server.js')"`).
- [ ] Signed run: `codesign --options runtime --entitlements installer/entitlements.plist --timestamp -s "Developer ID Application: …"` (deep, inside out); `productbuild --sign "Developer ID Installer: …"`; `xcrun notarytool submit --keychain-profile service-status --wait`; `xcrun stapler staple`; checks `spctl -a -vv -t install` → "accepted, source=Notarized Developer ID" and `codesign --verify --deep --strict`.

### Task 6: Release

- [ ] Publish code 2.1.0 to Stable (`latest.json`) so 2.1 shells don't fetch older code.
- [ ] `gh release create v2.1.0` with the pkg and notes; README install steps lose "Open Anyway" and gain Beta/Login notes.
- [ ] The user installs on the booth Mac (Admin password), sets Updates → Beta, and confirms Login Items.
